## Inference

### Temporal Localization via Sliding Window Inference

A CNN trained on discrete 3-second clips cannot inherently generate timestamps for a continuous 90-minute film. To achieve temporal localization across the entire runtime of *Come Drink with Me*, the system must employ a programmatic **Sliding Window Inference** protocol.

During the inference phase, the complete optical audio track of the film is loaded into memory. A Python script algorithmically slides a 3-second analytical window across the continuous audio array, utilizing a strict 1-second stride. The algorithm extracts the segment from `0.0s` to `3.0s`, computes the CQT via nnAudio2, and passes it to the trained ResNet-18 model, which outputs the dominant instrument. The window then advances by one second (analyzing `1.0s` to `4.0s`), and the prediction process repeats iteratively until the film concludes.

### Algorithmic Post-Processing

The raw output generated by the sliding window protocol is a continuous, discrete array of class predictions (e.g., `[erhu, erhu, xiao, erhu, erhu]`). This raw data stream inherently exhibits high temporal jitter; momentary fluctuations in the harmonic structure of an erhu glissando may cause the model to briefly misclassify a single 1-second frame as a xiao. To synthesize this raw data into a cohesive, professional annotation log, rigorous algorithmic post-processing must be applied:

1. **Median Filtering:** A one-dimensional median filter is executed across the prediction array. This highly effective nonlinear digital filtering technique evaluates a localized neighborhood of predictions and replaces the center value with the median of the surrounding labels. This mechanism effortlessly smooths out rapid, spurious misclassifications (false positives) while bridging momentary dropouts (false negatives) in sustained instrumental passages.

2. **Contiguous Merging:** Following the smoothing phase, a fusion algorithm iterates through the array, identifying consecutive blocks of identical predictions. These blocks are mathematically merged to synthesize definitive onset and offset timestamps. For instance, a continuous sequence of twenty pipa predictions is transformed into a single logged event denoting that the pipa is active from a specific minute and second to its conclusion.

3. **Heuristic Duration Thresholding:** Finally, a duration-based safety threshold is applied. Any merged acoustic event failing to meet a minimum temporal length (e.g., a sustained string prediction lasting less than 0.5 seconds) is classified as a statistical artifact and subsequently purged from the final annotation log.

### Graphical User Interface (GUI) Engineering

To render this complex computational pipeline usable, the system requires a sophisticated Graphical User Interface (GUI) that allows the human operator to visualize the audio, monitor the machine learning predictions, and manually adjust the generated timestamps. Building a performant, interactive application capable of rendering dense audio waveforms and high-resolution spectrograms in real-time necessitates the adoption of the **PyQt6** framework, specifically augmented by the **pyqtgraph** library.
