## Inference

### Temporal Localization via Sliding Window Inference

A CNN trained on discrete 3-second clips cannot inherently generate timestamps for a continuous 90-minute film. To achieve temporal localization across the entire runtime of *Come Drink with Me*, the system must employ a programmatic **Sliding Window Inference** protocol.

During the inference phase, the complete optical audio track of the film is loaded into memory. A Python script algorithmically slides a 3-second analytical window across the continuous audio array, utilizing a strict 1-second stride. The algorithm extracts the segment from `0.0s` to `3.0s`, computes the CQT via nnAudio2, and passes it to the trained ResNet-18 model, which outputs the dominant instrument. The window then advances by one second (analyzing `1.0s` to `4.0s`), and the prediction process repeats iteratively until the film concludes.

### Algorithmic Post-Processing

The raw output generated by the sliding window protocol is a continuous, discrete array of class predictions (e.g., `[erhu, erhu, xiao, erhu, erhu]`). To synthesize this raw data into a cohesive, professional annotation log, rigorous algorithmic post-processing is applied:

1. **RMS Silence Cropping:** Before passing a 3-second window to the CNN, its Root Mean Square (RMS) energy is calculated. If the energy falls below a minimum threshold of `0.005`, the window is classified as pure silence and skipped. This prevents the CNN from predicting random classes on background tape hiss or completely silent scenes.

2. **Categorical Mode Filtering:** A rolling mode filter (majority vote) with a kernel size of 3 is executed across the prediction array. This correctly smooths out rapid, spurious misclassifications for categorical data without hallucinating intermediate numerical classes (which is a risk with standard numerical median filters). 

3. **Contiguous Merging:** Following the smoothing phase, a fusion algorithm iterates through the array, identifying consecutive blocks of identical predictions. These blocks are mathematically merged to synthesize definitive onset and offset timestamps. For instance, a continuous sequence of twenty pipa predictions is transformed into a single logged event denoting that the pipa is active from a specific minute and second to its conclusion.

4. **Heuristic Duration Thresholding:** Finally, a duration-based safety threshold is applied. Any merged acoustic event failing to meet a minimum temporal length of 1.0 seconds is classified as a statistical artifact and subsequently purged from the final annotation log.

### Graphical User Interface (GUI) Engineering

To render this complex computational pipeline usable, the system is packaged into a web-based Graphical User Interface (GUI) powered by **Gradio**. This allows human operators to easily drag and drop audio files, visualize the waveform dynamically, and generate downloadable timestamp tables in a completely non-technical, browser-based environment.
